# Lessons: defects real reviewers found

Every entry is a defect a hub reviewer (or our own review) found after it had passed earlier checks. Pass P16 checks every entry against the change under review: for each one, say `checked: not present`, `checked: present` (a finding) or `not applicable` (with a reason, e.g. "no client code", or "pack se-plugin not loaded").

**The Pack column** says which reviews must check the row:
- `core`: every review, whatever the project kind. Most rows are here, because the pattern behind them (re-entrancy under a lock, in-place writes, enums by number, a sampled check) turns up in any language.
- `se-plugin`, `se-plugin/<host>`: reviews that loaded that pack or host note. Other reviews mark the row `not applicable (pack not loaded)`.

**Caught by** names DeepRules rules, tools and check files. `core/x.md` means `checks/core/x.md`; `se-plugin/x.md` means `packs/se-plugin/x.md`.

**Adding entries is mandatory.** Whenever a hub review, a user report or a later review finds something this skill missed, add an entry here (id, source, project, Pack, defect, pattern, how this skill catches it) and add or sharpen the check, tool rule or harness that would have caught it. Name the commit or PR. The newer packs (se-mod, pb-script, dotnet-app, dotnet-library, python, powershell, web) have no rows of their own yet; their first real misses go here.
